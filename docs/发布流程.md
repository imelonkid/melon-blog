# 发布流程

从 Obsidian 里写完一篇，到它出现在线上，中间该做什么、哪一步会挡住你。

## 一条命令

```bash
blog-deploy
```

等价于 `cd "$BLOG_REPO" && bash scripts/deploy.sh`，依次做：

```
同步 Obsidian  →  上线前检查  →  构建  →  探远端目录  →  上传  →  验证首页
```

**任何一步失败就停**，不会把半成品推上去。不要绕过它手敲 rsync——
2026-09-05 手敲错过一次路径，rsync 只报 `code 11 error in file IO`，
不说是路径不存在，而紧接着 curl 图片拿到 200（那张图早就在服务器上），
差点当成部署成功。脚本里的 `test -d` 就是为这个加的。

## 文章的两种状态

这是两套独立的开关，别搞混：

| 字段 | 写在哪 | 管什么 |
|---|---|---|
| `publish: true` | Obsidian 的 markdown | 要不要从 Obsidian 同步到博客仓库 |
| `draft: true` | 博客仓库 `src/content/posts/` | 同步过来后，要不要进构建产物 |

- **没标 `publish`** —— 同步时跳过，博客仓库里根本不会出现。改回 false
  之后再同步，之前生成的文件会被自动删掉。
- **`draft: true`** —— 只在本地 `pnpm dev` 可见，**不上线**。用来验证排版、
  公式、图表效果。`_demo-math-mermaid.md` 就是常驻的渲染样例，本地随时能开。
  preflight 会检查 draft 有没有漏进 `dist/`。

## 两个时间

| 字段 | 含义 | 谁来填 | 会不会变 |
|---|---|---|---|
| `date` | 发表日 | 写文章时 | **上线后永不改** |
| `updated` | 实质修改日 | 审阅时自动写回 | 每次实质修订 |

**为什么不能用 `date` 兼任更新时间**：它决定首页排序和 RSS 的 `pubDate`。
改个错别字就把 `date` 往后挪，这篇会跳回首页顶部、RSS 订阅者会收到一次
「新文章」推送。那是在骗读者。

`updated` 写入的条件是三条同时成立：已经上线过、正文 SHA-1 变了、
执行了 `review-scan --mark`。草稿阶段改来改去不算。

页面上显示成「更新于 X」，只在它晚于 `date` 时出现。preflight 会拦住
`updated` 早于 `date` 的情况。

**还原一次改动也算改动**——把正文改回原样再 `--mark` 同样会写 `updated`，
这是对的，但做实验时记得手动删掉那行。

## 上线前必须审阅

**每篇都要过 `/article-review`，没有例外。** preflight 会核对审阅记录：
标了 `publish: true` 却没审过、或者审完又改了正文的，直接挡住发布。
"先发了回头再看" 走不通，这是故意的。

审阅记录按**正文 SHA-1** 判定，存在 `.article-review.json`：
改一个字就要重审，只动 frontmatter（比如把 publish 翻成 true）不触发。

## preflight 查什么

```bash
pnpm run preflight
```

每一条都对应踩过的坑：

| 检查 | 因为什么加的 |
|---|---|
| 缺图标记 | Obsidian 挪动附件后链接变成 `![[子目录/图.png]]`，同步匹配不上，图没了 |
| 图片断链 | 正文引用的 `/images/...` 在 `public/` 下不存在 |
| 百分比宽高 | 老文章的裸 `<img width="80%">`，浏览器算不出高度，刷新时页面会跳 |
| 未审阅 | 见上一节 |
| draft 泄漏 | 本地预览用的草稿混进构建产物 |

`.image-exceptions.json` 记录 2017 年迁移时**源头就丢了**的老图（JVM 4 张 +
PlanUML 1 张）。那不是绕过检查的口子——**新文章断链一定是同步或路径出了问题，
去修，不要往里加。**

## 服务器坐标

全部是环境变量，定义在 `~/.zsh/conf.d/env.zsh` 的「纸上得来」一段。
仓库是公开的，所以代码和文档里只出现变量名。换服务器只改那一个文件。

| 变量 | 是什么 |
|---|---|
| `BLOG_REPO` | 博客仓库本地路径 |
| `BLOG_VAULT` / `BLOG_SRC` | Obsidian vault 根目录 / 草稿目录 |
| `BLOG_SITE` | 站点地址 |
| `BLOG_SSH` | SSH 别名，主机、用户、密钥都在 `~/.ssh/config` 里 |
| `BLOG_WEBROOT` | 站点根目录 |
| `BLOG_NGINX_CONF` | 站点 nginx 配置 |
| `BLOG_PANEL_PORT` / `BLOG_PANEL_ENTRY` | 面板端口与安全入口 |

**`BLOG_WEBROOT` 是站点根，不是应用安装目录那一层。** 两者路径相似，
写错时 rsync 只说 IO 错误，不会说路径不存在。

## 面板

```bash
panel
```

走 SSH 隧道，面板端口不对公网开放。保持终端开着，Ctrl+C 断开。
浏览器开 `http://localhost:<BLOG_PANEL_PORT><BLOG_PANEL_ENTRY>`——
少了安全入口那一段会看到 "Access Temporarily Unavailable"。

## 改服务器配置

nginx 配置在 `$BLOG_NGINX_CONF`。**改之前先备份**：

```bash
ssh "$BLOG_SSH" "cp \$BLOG_NGINX_CONF \$BLOG_NGINX_CONF.bak-\$(date +%Y%m%d-%H%M)"
```

改完 `nginx -t` 通过再 reload。仓库里的 `deploy/openresty.conf` 是参考副本，
不会自动同步到服务器，改完记得两边对齐。
